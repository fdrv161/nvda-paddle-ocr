# План: дополнение NVDA «Paddle OCR» (минимум NVDA 2026.3, 64 бит)

## Зачем
Windows OCR в NVDA часто ошибается. PaddleOCR (PP-OCRv6) читает заметно лучше. Делаем дополнение,
которое работает **так же, как Windows OCR**, только с другим движком. Главное — скорость и стабильность.

## Почему 2026.3
В 2026.3 захват для OCR работает при шторке и встроенной лупе (#20630, #20664). Если система так не умеет,
NVDA сама просит отключить шторку. Мы получаем это бесплатно, потому что идём через стандартный `contentRecog.recogUi`.

## Как устроено
- Всё на Python внутри NVDA, без своих .exe.
- В `lib/` лежат колёса cp313 win_amd64: `onnxruntime 1.30.0`, `numpy 2.5.3`, `opencv-python-headless 5.0.0.93`.
- Свой короткий конвейер по образцу rapidocr: найти строки → прочитать строки.
- Свой `ContentRecognizer` → `recogUi.recognizeNavigatorObject()` → `LinesWordsResult`.
  Окно результата, клик по слову, автообновление и шторка — всё как у NVDA+R.

## Модели (все внутри)
- Детектор строк: PP-OCRv6.
- «Русский и английский»: PP-OCRv6 RU (vladlinv).
- «Многоязычный» (латиница, китайский, японский): официальная PP-OCRv6.
- Один размер моделей (tiny, small или medium) выбираем по замерам на этапе 0. Переключателя качества в первой версии нет.

## Как у Windows OCR
- Две команды, обе без жеста по умолчанию: «Распознать объект навигатора» и «Переключить язык OCR».
- Настройки: язык, автообновление, читать результат сразу.
- На защищённом экране дополнение ничего не делает.

## Загрузка и память
- Библиотеки и модели загружаются при первом запросе, а не при старте NVDA.
- После загрузки модели остаются в памяти, поэтому следующие запросы быстрые.
- Временную память после каждого распознавания возвращаем системе (настройка onnxruntime).
- Сколько всего занимает, меряем на этапе 0. Выгрузку добавим, только если окажется много.

## Стабильность
- Распознавание в фоновом потоке; один запрос за раз.
- Ошибка → сообщение и запись в журнал, NVDA продолжает работать.

## Координаты (чтобы клик попадал)
- Если картинку уменьшаем для детектора, рамки умножаем обратно на тот же коэффициент.
- Рамки на одной высоте собираем в одну строку и сортируем слева направо.
- Слова внутри рамки делим пропорционально буквам.
- Тест: текст в известных местах на картинках 1080p и 4K. Рамки слов должны совпасть.

## Файлы `paddleOcr/`
- `addon/globalPlugins/paddleOcr/`
  - `__init__.py` — команды, настройки
  - `recognizer.py`
  - `engine.py` — без NVDA, можно тестировать отдельно
  - `lib/`, `models/`
- `tools/` — скачать библиотеки и модели, замеры; `tests/`. Для разработки — `.venv` проекта.

## Этапы
0. Замеры вне NVDA — **готово**. Модели: «Русский и английский» = det_v6_tiny + rec_eslav_v5
   (экран 1080p 0.5–0.85 с, ~100 МБ); «Многоязычный» = det_v6_tiny + rec_v6_tiny (0.2–0.3 с, ~90 МБ).
   small/medium и INT8 не берём (медленнее, а INT8 ещё и ломает текст). Потоки — авто, пачка строк — 4.
   Движок: `addon/globalPlugins/paddleOcr/engine.py`, замеры: `tools/bench.py`.
   Известная мелочь: куски только из букв-двойников (Bce/Все) иногда не в той азбуке.
1. Команда → текст голосом (`ui.message`).
2. Окно результата, клик по словам.
3. Языки, настройки, документация ru/en.
4. Сборка `.nvda-addon`, проверка в 2026.3, лицензии.

## Проверка
- `pytest tests/`.
- Замер: окно 1920×1080 распознаётся быстрее 0.5 с.
- В NVDA 2026.3:
  - старт NVDA не медленнее, чем без дополнения;
  - распознавание, клик по словам, переключение языка;
  - работа при шторке;
  - 20 запросов подряд без роста памяти;
  - журнал без ошибок.
